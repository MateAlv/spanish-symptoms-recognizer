## This does not reproduce the documented 0.752

`tests/README.md` reports 0.752 for the best configuration. This run scores
0.588 on the same dataset. The gap is not yet explained, and the difference
matters enough that the headline number should not be quoted until it is.
Candidate causes, none verified:

- a different `text_parser` or prompt than the one recorded
- the README's figure being a text-F1 or per-document average rather than the
  micro code F1 computed here
- model drift: the benchmark ran on an earlier `claude-opus-5` snapshot

## The shape of the error is the useful finding

Recall is 0.848 and precision 0.451: the module finds nearly everything the
gold standard lists, then adds roughly as much again. The additions are not
noise. From `historia_1` (18 FPs), checked against the source text:

| Predicted | Gold standard | Reading |
|---|---|---|
| HP:0002293 Alopecia of scalp | HP:0001596 Alopecia | same finding, finer grain |
| HP:0001698 Pericardial effusion | HP:0001701 Pericarditis | related finding |
| HP:0000980 Pallor | — | text says "palidez severa" |
| HP:0001063 Acrocyanosis | — | text says "cianosis distal" |
| HP:0000790 Hematuria | — | present in the text |

The gold standard annotates "palidez severa seguida de cianosis distal" as the
single code HP:0030880 (Raynaud phenomenon). Extracting the two component
findings is defensible clinically and counted as two false positives here.

So the measured precision is a floor, not an estimate. A reviewer would have
to adjudicate each FP to know the real figure.

## What the number can and cannot support

The evaluator compares **sets of codes per document** (`evaluator.py:86`). It
never checks that a code was attached to the right mention, and a duplicated
phenotype cannot be penalised. With 59 gold mentions across 8 documents, two
or three adjudications move F1 by several points.

Usable for ranking configurations against each other. Not sufficient on its own
to justify replacing the incumbent.

## Cost profile

805s for 8 short histories, at one LLM call per sentence plus one per mention.
That is ~100s per history, against the ~28s measured for a single history run
alone — the difference is the rate limiter doing its job.

This cannot sit in a synchronous browser request, which `docs/LLM_ACCESS.md`
already anticipated.

## What would make this decisive

1. **Score the incumbent on the same 8 histories.** Without it there is no
   baseline, and "0.588" answers no question on its own.
2. **Adjudicate the false positives.** A clinician marking each FP as correct,
   over-specific, or wrong converts the precision floor into a real number.
3. **Explain the 0.752 gap** before either figure is quoted anywhere.
